Issues Found & Resolved

1. Pagination — RESOLVED

Old code used fake p-limit and p-page params. While not in the Swagger spec, we discovered p-size DOES work across all endpoints. Default page size is ~10, which caused dropdowns to show only 10 items. Fix: p-size=200 on all vehicle endpoints. Response includes MoreItems: true/false.

2. Wrong Parameter Names — RESOLVED

All param names corrected in api-client.js: i-price, i-img, f-query, f-andSegmentTags, f-minPrice, f-maxPrice, f-minSpeedRating.

3. Fabricated Endpoints — RESOLVED

Removed fake endpoints. Vehicle-to-tire lookup now uses the correct two-step flow: /vehicles?i-fitments=true → extract TireSize from Fitments[] → /tires?f-sizes={sizes}.

4. API Key — RESOLVED

Corrected from "holbrook" to "holbrooktire" in config.js.

5. Wheels Integration — RESOLVED

All 4 wheel endpoints wired up in api-client.js. Wheel brands display with logos on brands.html and wheels.html. 107 wheel brands active.

Key Implementation Notes
p-size is critical: Not in the Swagger spec but works on ALL endpoints. Default page size is ~10. Without p-size=200, vehicle dropdowns show only ~10 makes/models. Always include it.
Brand logos follow a pattern: URL = BrandLogosUrlBase + Brand.replace(/ /g, '_') + '.webp'. Works for all 120 brands (13 tire + 107 wheel). Both /tires/brands and /wheels/brands support i-logos=true.
Image URLs require i-img=true: The ImgUrlBase field only appears in responses when i-img=true is passed. Full image URL = ImgUrlBase + ImgThumb (or ImgAngle, ImgFront, ImgSide1, ImgSide2).
API returns PascalCase: All response fields are PascalCase (Brand, Model, Price, ImgThumb). The normalization layer in api-client.js converts to lowercase for display code.
Tire size formats: Three formats in the data: Metric (P275/60R20, 225/35ZR20), Flotation (31X10.50R15LT), and Bias/Commercial (11L-14, 10R22.5). The Z in ZR sizes must be handled in parsing (e.g., regex: Z?[RBD]).
Client-side years recommended: The /vehicles/years endpoint returns limited results even with p-size. Generate years client-side (current year + 1 down to 1960) for full coverage.

Correct API Flow for "Search by Vehicle"

1. Generate years client-side (2027 → 1960) — don't use /vehicles/years
2. GET /vehicles/makes?f-year=2025&p-size=200 → populate make dropdown (43 makes for 2024)
3. GET /vehicles/models?f-year=2025&f-make=Chevrolet&p-size=200 → populate model dropdown (20 models)
4. GET /vehicles/submodels?f-year=2025&f-make=Chevrolet&f-model=Silverado+1500&p-size=200 → populate submodel dropdown
5. GET /vehicles?f-year=2025&f-make=Chevrolet&f-model=Silverado+1500&f-submodel=LT&i-fitments=true → get OEM tire sizes from Fitments[].TireSize
6. GET /tires?f-sizes=275/60R20&i-img=true&i-price=true&i-specs=true → get matching tires with images and pricing

Correct API Flow for "Search by Size"

1. GET /tires?i-specs=true&p-size=500 → fetch all tires, extract unique Size values
2. Parse sizes into cascading columns using parseSize() — handles metric, ZR, flotation, bias, commercial
3. Populate first dropdown with unique col1 values, cascade col2 and col3 on selection
4. GET /tires?f-sizes={selectedSize}&i-img=true&i-price=true&i-specs=true → get matching tires
